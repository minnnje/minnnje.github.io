알바 출퇴근 자동 기록 웹앱

Status in-progress
Stack Next.js, FastAPI, Google Sheets API, Google Drive API

  • Nextjs
  • Google-Sheets-Api
  • Google-Drive-Api

무엇을 만들었나

아르바이트생이 출근·퇴근 시 사진을 찍고 “출근”/“퇴근” 버튼만 누르면, 서버 시간 기준으로 시간과 사진이 자동 기록되는 웹앱. 최종 산출물은 매일매일 쌓이는 구글시트 출퇴근 기록부이고, 사장님은 별도 관리자 화면 없이 공유받은 시트를 열어보는 것만으로 누가 언제 출퇴근했는지 확인한다.

현재 상태: 설계는 확정했고 구글 클라우드(서비스 계정, Sheets API, Drive API) 연동 설정까지 마쳤다. 프론트엔드/백엔드 코드 구현은 아직 착수 전.

왜 만들었나 (동기/문제의식)

원래는 매장 카카오톡 단체방으로 출퇴근 시각과 사진을 보고받고 있었는데, 카카오는 일반 그룹채팅방 메시지를 읽어오는 공식 API를 제공하지 않는다. 비공식 크롤링/매크로는 약관 위반 및 계정 정지 리스크가 있어 배제하고, 입력 경로만 자체 웹앱으로 옮기기로 했다. 카톡방에는 체크인 페이지 링크만 고정 공유한다.

어떻게 만들었나 (아키텍처/설계 결정)

설계 과정에서 몇 차례 방향을 바꿨다.

  1. 직원 체크인 인증 — PIN 제거: 소규모 신뢰 기반 매장이라 대리출퇴근 위협이 낮다고 판단해 PIN 없이 이름 입력만으로 체크인하도록 함. 대신 서버 시간 기준 타임스탬프로 클라이언트 시간 조작을 막고, 사진은 사후 확인용 증거로 남긴다.
  2. 이름 입력 — 콤보박스 자동완성: 완전 자유 입력은 오타로 동일인이 여러 이름으로 흩어져 근무시간 집계가 깨지고, 고정 드롭다운은 관리자가 매번 직원을 등록/수정해야 하는 부담이 있다. 절충으로 기존 이름 자동완성 + 목록에 없는 이름이면 1회 컨펌 후 신규 등록하는 방식을 택함.
  3. 관리자 대시보드 — 아예 제거: 처음엔 “로그인 없는 공개 URL” vs “ID/PW 로그인” 두 옵션을 저울질했는데, 실제로 필요한 건 사장님이 기록을 보는 것뿐이라는 걸 재확인하고 관리자 웹페이지/로그인을 통째로 없앴다. 대신 기록용 구글시트를 사장님 계정에 직접 공유해서, 접근 제어 자체를 구글 공유 권한에 위임했다.
  4. 저장소 — DB/오브젝트 스토리지 대신 Google Sheets + Drive: 처음엔 SQLite → Postgres, 사진은 서버 디스크 → S3 같은 전형적인 구성으로 시작했다. 그런데 무료 티어 배포 환경(Render 등)에서는 재배포 시 디스크가 초기화될 수 있다는 문제가 있어서, DB와 오브젝트 스토리지를 아예 없애고 Google Sheets를 기록의 단일 소스, Google Drive를 사진 저장소로 쓰는 방향으로 바꿨다. 이름 자동완성도 시트에서 바로 읽어온다. 결과적으로 백엔드가 완전 무상태(stateless)가 되어 배포/운영이 단순해졌다.
  5. 구글 연동: OAuth 사용자 인증 흐름 대신 서비스 계정(Service Account)을 만들어 JSON 키를 발급받고, 대상 시트/드라이브 폴더에 서비스 계정 이메일을 편집자로 공유하는 방식을 택했다. 키 만료나 재동의 이슈 없이 서버가 계속 접근할 수 있다.

배운 점 / 어려웠던 점

아직 구현 전 설계 단계라 실제 트러블슈팅 경험은 없다. 지금까지 요구사항을 좁혀가며 얻은 것들만 남긴다.

  • “무료로 배포하고 싶다"는 제약 하나가 저장소 선택(재배포 시 디스크가 초기화되는지 여부)을 흔들고, 그게 아키텍처 전체를 바꾸는 계기가 될 수 있다. 이 프로젝트에서는 상태 자체를 서버 밖(Google)으로 밀어내는 선택으로 이어졌다.
  • 보안 요구사항 중에는 팀 신뢰도와 무관하게 항상 지켜야 하는 것(사진 EXIF 제거, UUID 파일명 등)과, 위협 모델에 따라 조정 가능한 것(PIN 유무, 관리자 인증 수준)이 있는데, 이 둘을 구분해서 판단하니 결정이 훨씬 빨라졌다.

다음 개선 방향

  • 프론트엔드/백엔드 분리 레포 세팅
  • 백엔드: 구글시트 이름 목록 읽기(자동완성), POST /records/check(사진 업로드 → EXIF 제거 → 드라이브 저장 → 시트에 행 추가) 구현
  • 프론트엔드: 체크인 페이지(콤보박스 + 신규 직원 컨펌 모달 + 카메라 촬영 + 출근/퇴근 버튼) 구현
  • 90일 지난 사진/기록 자동 삭제 스케줄 스크립트
  • Vercel + Render 배포, 로컬(맥북)에서 엔드투엔드 테스트
  • 안정화 후 시트/드라이브 공유 대상을 사장님 계정으로 전환, 실사용 전환
