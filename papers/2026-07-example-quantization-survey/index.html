한 줄 요약

PTQ(Post-Training Quantization)의 주요 접근법들을 정리한 예시 문서입니다. 실제 논문 대신 레이아웃/수식/코드 렌더링 테스트용 더미 콘텐츠입니다.

문제 정의 (Problem)

LLM의 파라미터를 FP16에서 INT8/INT4로 양자화할 때, 재학습 없이(post-training) 정확도 손실을 최소화하는 것이 핵심 과제입니다.

핵심 아이디어 (Method)

가중치 \(W\)를 스케일 팩터 \(s\)로 양자화하는 기본 수식은 다음과 같습니다.

$$ W_q = \text{round}\left(\frac{W}{s}\right), \quad s = \frac{\max(|W|)}{2^{b-1} - 1} $$

여기서 \(b\)는 목표 비트 수입니다. 인라인 수식도 이렇게 \(s\) 처럼 문장 중간에 쓸 수 있습니다.

Weight-only Quantization

RTN(Round-To-Nearest)과 GPTQ가 대표적입니다. Activation은 FP16을 유지하고 weight만 저비트로 낮추기 때문에 구현이 단순하고, 메모리 절감 효과가 커서 온디바이스/서빙 환경에서 가장 먼저 시도되는 방식입니다. GPTQ는 Hessian 기반 오차 보정을 레이어 단위로 순차 적용해 RTN 대비 손실을 크게 줄입니다.

Weight-Activation Quantization

SmoothQuant 계열은 activation의 outlier를 weight 쪽으로 스케일을 옮겨 흡수시킨 뒤 양쪽을 함께 저비트로 양자화합니다. Weight-only보다 구현이 복잡하지만, INT8 커널을 그대로 활용할 수 있어 연산 자체의 속도 이득까지 얻을 수 있다는 차이가 있습니다.

실험 결과 (Results)

방법 비트 Perplexity
FP16 (baseline) 16 5.68
RTN 4 6.12
GPTQ 4 5.81

Perplexity 비교

비트 수가 같을 때 GPTQ가 RTN보다 일관되게 낮은 Perplexity를 보입니다. 특히 4bit 구간에서 격차가 가장 크게 벌어지는데, 이는 레이어별 오차 보정이 저비트일수록 더 큰 역할을 하기 때문으로 해석됩니다.

Latency / 메모리 비교

FP16 대비 4bit 양자화 모델은 메모리 사용량이 약 1/4 수준으로 줄어듭니다. 다만 Weight-only 방식은 연산 자체가 여전히 FP16 커널을 쓰는 경우가 많아 latency 개선폭이 메모리 절감폭만큼 크지 않을 수 있습니다.

내 생각 / 한계점

  • Activation outlier 처리 방식에 따라 실제 정확도 편차가 크다.
  • Weight-only quantization과 Weight-Activation quantization 구분해서 봐야 함.

import torch

def quantize_tensor(w: torch.Tensor, bits: int = 4):
    qmax = 2 ** (bits - 1) - 1
    scale = w.abs().max() / qmax
    w_q = torch.round(w / scale).clamp(-qmax - 1, qmax)
    return w_q, scale
