읽기 순서

  • 문제: FP16 학습 시 작은 gradient 값이 0으로 underflow되는 문제
  • 방법: loss scaling으로 gradient 크기를 표현 가능한 범위로 끌어올림
  • 결과: FP32 대비 메모리 절반, 정확도 손실 거의 없음

문제 정의 (Problem)

FP16은 지수부(exponent) 범위가 좁아서, 작은 값을 갖는 gradient가 backward 과정에서 0으로 반올림(underflow)되어 학습이 불안정해질 수 있습니다.

Loss Scaling

Loss \(L\)에 스케일 팩터 \(s\)를 곱해 backward를 수행하고, optimizer step 직전에 gradient를 다시 \(s\)로 나눠줍니다.

$$ g = \frac{1}{s} \nabla_\theta (s \cdot L) $$

Master Weight 유지

master weight는 FP32로 유지하면서 forward/backward 연산만 FP16으로 수행하는 mixed-precision 구조가 핵심입니다.

실험 결과 (Results)

설정 정밀도 메모리 정확도 손실
Baseline FP32 1.0x -
Naive FP16 FP16 0.5x 학습 발산
Mixed + loss scale FP16/FP32 0.55x 거의 없음

핵심 기여

  • 정적/동적 loss scaling 방식을 비교하고 동적 스케일링이 더 안정적임을 보임.

내 생각 / 한계점

  • 동적 loss scaling은 스케일 값이 발산 임계치를 넘나들 때 step을 몇 번 건너뛰는 overhead가 있어, 실제 처리량 이득은 이론치보다 작을 수 있음.
