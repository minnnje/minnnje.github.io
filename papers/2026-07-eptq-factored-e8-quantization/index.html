EPTQ: Fast and Accurate 2-bit Post-Training Quantization via Factored E8 Lattice

Venue CIKM 2026 (submission, double-blind)
Authors Anonymous Author(s)
Status to-implement
2026. 7. 30 · 17분 읽기
  • Quantization
  • Post-Training Quantization
  • Vector-Quantization
  • Llm-Compression

1. 한줄 요약

\(E_8\) 격자 코드북을 손실 없이 4KB로 재구성한 Factored-\(E_8\)(FE8)에, Sinkhorn-Knopp 기반 행/열 스케일 정규화와 Kneedle 기반 매트릭스별 adaptive critical weight preservation을 결합하여, 2-bit PTQ에서 “VQ급 정확도 + FP16을 능가하는 추론 처리량 + scalar 방법에 가까운 양자화 속도"를 동시에 달성한 논문입니다.

2. 읽기 전에 알아두면 좋은 배경지식 (Prerequisite)

  • PTQ (Post-Training Quantization): 재학습 없이 사전학습된 모델의 가중치를 저비트로 변환하는 것. Calibration용 입력 \(X\)만 소량 사용해서 양자화 오차를 최소화하는 파라미터(스케일, 클리핑 등)를 찾는다.
  • Scalar vs Vector Quantization: Scalar는 가중치 하나하나를 독립적으로 양자화(RTN, GPTQ, AWQ, OmniQuant). Vector Quantization(VQ)은 여러 가중치를 묶은 벡터 단위로 코드북에서 가장 가까운 점을 찾아 양자화(VPTQ, QTIP, AQLM). 이 논문의 핵심 배경은 “고차원 Vector 양자화가 저차원 Scalar 양자화보다 기하학적으로 유리하다"는 사실이다.
  • 격자 양자화(Lattice Quantization) / Sphere Packing: n차원 공간을 규칙적인 격자점으로 채우는 방법. 같은 점 개수라면 점들이 공간을 얼마나 빈틈없이 채우는지(packing density)에 따라 양자화 오차가 달라진다. \(E_8\) 격자는 8차원에서 증명된 가장 촘촘한 sphere packing이라, 원점 주변에 밀집하는 Gaussian 분포의 가중치를 표현하기에 이론적으로 가장 효율적이다.
  • GPTQ 스타일 Hessian 오차 보정: 한 가중치(또는 벡터)를 양자화한 뒤 생긴 오차를, 아직 양자화하지 않은 나머지 가중치에 Hessian 역행렬 비율만큼 분산시켜 전체 reconstruction error를 최소화하는 기법. Cholesky 분해로 열 단위 순차 처리가 가능해 대형 모델에도 확장된다.
  • Sinkhorn-Knopp 알고리즘: 행렬을 doubly stochastic(행/열 합이 모두 1)하게 만들기 위해 행/열 정규화를 번갈아 반복 적용하는 알고리즘. 원래는 최적수송 문제에서 쓰이지만, 이 논문은 “행/열의 \(L_1\) 노름을 균일하게 맞춘다"는 목적에 같은 반복 구조를 재사용한다.
  • Kneedle 알고리즘: 값이 정렬된 곡선에서 “완만하게 꺾이는 지점(knee point)“을 자동으로 찾는 방법. 이 논문에서는 중요도 점수 분포에서 “여기부터는 중요도가 거의 없다"로 볼 수 있는 지점을 사람이 임계값을 정하지 않고 자동으로 찾는 데 쓰인다.

3. 문제 배경 및 정의

3-1. 기존 방법들이 왜 부족한가 (Motivation)

논문은 관련 연구를 4개 계열로 나눠 각각의 한계를 짚습니다(Section 2).

  1. Scalar Quantization (OBQ, GPTQ, OmniQuant, SpQR, SEPTQ) :

    개별 가중치를 독립적으로 반올림하기 때문에, LLM 가중치가 실제로는 고차원 공간에서 특정 방향으로 뭉쳐 있는 분포(High-dimensional weight distribution)를 표현하지 못합니다. 격자점이 좌표축에 정렬된 정육면체 grid 형태이기 때문에, 원점 중심의 구형(spherical) 분포와 기하학적으로 맞지 않는다는 게 근본 원인입니다. 그 결과 2-bit처럼 극단적인 저비트에서는 catastrophic performance collapse가 나타납니다.

  2. Vector Quantization (AQLM, GPTVQ, VPTQ, QuIP#, QTIP) :

    벡터 단위 코드북으로 기하학적 문제는 해결하지만, VPTQ는 코드북 자체를 데이터로부터 반복 최적화로 학습해야 해서 양자화에 수 시간이 걸리고, QTIP은 Trellis-Coded Quantization의 복잡한 디코딩 파이프라인 때문에 추론 처리량이 크게 제한됩니다.

  3. Distribution Adjustment (SmoothQuant, AWQ, QuaRot, QuIP):

    activation outlier를 weight 쪽으로 옮기거나(SmoothQuant/AWQ), Hadamard 회전으로 분포를 incoherent하게 만드는(QuaRot/QuIP) 방식. 이 논문이 다루는 weight 행/열 간 분산 불균형 문제와는 다른 축의 문제를 풉니다.

  4. Critical Weight Preservation (SpQR, SEPTQ):

    Hessian sensitivity가 높은 가중치를 골라 고정밀도로 남겨두는 방식. 그런데 SpQR은 전역 고정 임계값, SEPTQ는 전역 고정 비율(top-p%)을 쓰기 때문에, sublayer/layer마다 실제로 다른 중요도 분포 형태를 반영하지 못하고, 보존 마스크 저장에 추가 비트 오버헤드가 듭니다.

EPTQ는 이 네 계열의 아이디어를 각각 하나씩 개선해서 조합합니다: VQ의 기하학적 장점(1) + 실용적인 스케일 정규화(2)로 대체 + (3)의 아이디어를 weight 쪽에 적용 + adaptive한 critical weight preservation(4)으로 대체.

3-2. 이 논문이 푸는 정확한 문제 (Problem Statement)

선형 레이어의 가중치 \(W \in \mathbb{R}^{d_{out} \times d_{in}}\)와 calibration 입력 \(X \in \mathbb{R}^{d_{in} \times n}\)이 주어졌을 때, 이 레이어 출력에 대한 reconstruction error를 최소화하는 양자화된 가중치 \(\widehat{W}\)를 찾는 것이 목표입니다.

$$ \arg\min_{\widehat{W}} \; \lVert WX - \widehat{W}X \rVert_F^2 \quad \text{s.t.} \quad \widehat{W} = \text{quant}(W) $$

여기서 중요한 점은 목적함수가 “가중치 자체의 오차”(\(\lVert W - \widehat{W} \rVert\))가 아니라 “그 레이어를 통과한 출력의 오차”(\(\lVert WX - \widehat{W}X \rVert\))라는 것입니다. 즉 calibration 데이터의 실제 activation 분포 \(X\)를 반영해서, 모델 출력에 영향이 큰 가중치 방향의 오차를 더 강하게 억제하도록 설계되어 있습니다. 이 정의는 GPTQ 계열과 동일하고, EPTQ는 여기에 \(\widehat{W}\)를 만드는 quant(·) 함수 자체를 \(E_8\) 격자 기반으로, 그리고 어떤 가중치는 아예 양자화하지 않는 조건부 함수로 새로 설계합니다.

3-2-1. 기호 정리

  • \(W \in \mathbb{R}^{d_{out} \times d_{in}}\)
    Linear layer(신경망의 완전연결층) 하나의 가중치 행렬. 이 레이어는 입력 벡터 하나(길이 \(d_{in}\))를 받아서 \(Y=Wx\)로 출력 벡터(길이 \(d_{out})\)를 생성.
  • \(X \in \mathbb{R}^{d_{in} \times n}\)
    calibration 입력 — 실제 서비스에서 이 레이어에 들어올 법한 입력 예시 \(n\)개를 골라, 각각을 열(column)로 쌓아놓은 행렬. PTQ는 재학습을 안 하니까, 대신 이런 소량의 진짜 입력 샘플을 갖고 양자화해도 출력이 크게 안 변하게 조정합니다 — 배경지식 섹션의 PTQ 설명과 같은 맥락
  • \(WX\)
    그 \(n\)개 입력 각각에 대해 이 레이어를 통과시킨 실제 출력들을 한 번에 쌓은 것. 행렬곱이라 한 번에 계산됩니다.
  • \(\widehat{W}\)
    \(W\)를 저비트로 양자화한 버전. \(\text{quant}\)\((\cdot\)) 은 양자화한다는 함수를 뜻하는 표기
  • \((\lVert \cdot \rVert_F^2)\) (Frobenius norm 제곱)
    행렬의 모든 원소를 제곱해서 다 더한 것. 행렬을 그냥 하나의 긴 벡터로 펼쳤을 때의 L2 노름 제곱과 똑같습니다.

3-2-2. 왜 “가중치 오차"가 아니라 “출력 오차"일까

양자화가 잘 됐다는 것은 \(\lVert W - \widehat{W} \rVert\) 로 단순히 생각할 수 있을 겁니다. 그런데 이 논문(그리고 GPTQ 계열 전체)은 그렇게 하지 않고 \(\lVert WX - \widehat{W}X \rVert\) , 즉 그 가중치들이 실제로 입력과 곱해진 뒤의 결과가 얼마나 차이 나는지를 씁니다.

왜 이 차이가 중요한지 직관적으로 살펴봅시다:

  • 어떤 가중치 \(W_{i,j}\)가 곱해지는 입력 성분(\(X\)의 \(j\)번째 행)이 실제 데이터에서 항상 \(0\) 에 가깝다면, 이 가중치를 아무리 양자화로 뭉갠다 해도 (\(0\) 에 가까운 값과 곱해지니까) 출력에는 거의 영향이 없습니다.
  • 반대로 어떤 가중치가 곱해지는 입력 성분이 크고 자주 나타난다면, 그 가중치의 아주 작은 오차도 출력에서는 크게 증폭됩니다.

즉 가중치 값 자체의 오차는 이런 차이를 전혀 구분하지 못하는데, 출력 오차는 실제 데이터 \(X\)를 곱해서 계산하기 때문에 어느 가중치가 실제로 중요한지를 자동으로 반영합니다. 이게 바로 배경지식 섹션에 있던 “calibration용 입력 \(X\)만 소량 사용해서 양자화 오차를 최소화하는 파라미터를 찾는다"는 문장의 실체이고, 이후 4.1절의 Hessian 보정식((H=2XX^\top))과 4.3절의 importance score(([XX^\top]^{-1})이 분모에 들어감)가 전부 이 목적함수에서 파생된 것입니다 — (X)를 곱한 채로 오차를 재기 때문에, “이 가중치가 얼마나 자주/크게 쓰이는가"를 담고 있는 (XX^\top)이 자연스럽게 수식 곳곳에 다시 등장하는 겁니다.

  1. “s.t. (\widehat{W} = \text{quant}(W))“의 의미

이 조건은 “아무 실수 행렬이나 골라도 된다"가 아니라, 양자화 함수가 실제로 만들어낼 수 있는 값들 중에서만 (\widehat{W})를 고를 수 있다는 뜻입니다. 예를 들어 2-bit 양자화라면 (\widehat{W})의 각 값은 극소수의 후보값(코드북) 중 하나여야 하니, 자유롭게 아무 실수나 쓸 수 있는 게 아니라는 제약입니다. 그래서 이 문제는 “(\widehat{W})를 자유롭게 최적화"하는 게 아니라, 사실상 어떤 양자화 함수(quant)를 설계해야 이 오차가 작아지는가를 묻는 문제입니다.

  1. 마지막 문단이 말하는 것 “이 정의는 GPTQ 계열과 동일하 출력 오차 최소화)는 EPTQ가 새로 만든 게 아니라 GPTQ부터 이어져 진짜 기여는 이 문제를 푸는quant(·) 함수 내부를 어떻게 설계했는가에 있습니다 — (1) (E_8) 격자 기반으로 벡터 단위 양자화를 하고, (2) 일부 가중치는 아예 양자화 대상에서 빼고 FP16으로 남기는 조건부 로직까지 quant(·) 안에 넣었다 FE8/스케일 정규화/criticalweight preservation 세 가지가 전부 “이 3-2절 목적함수를 최소화하기 위한 quant(·)의 구체적인 구현"입니다.

4. 핵심 아이디어 (Method)

4-1. 논문 소제목 구조를 따라 설명

4.1 Factored-\(E_8\) (FE8) Quantization. \(E_8\) 격자는 다음과 같이 정의됩니다.

$$ E_8 = \left\{ x \in \mathbb{Z}^8 \cup \left(\mathbb{Z} + \tfrac{1}{2}\right)^8 \;\middle|\; \mathbf{1}^{\top}x \equiv 0 \pmod 2 \right\} $$

이 논문의 핵심 관찰은 \(E_8\)이 8차원 벡터를 4+4차원으로 쪼갠 두 개의 4차원 coset(부분격자)의 곱으로 정확히 분해된다는 것입니다.

$$ E_8 = \bigsqcup_{t=0}^{3} F_t \times F_t $$

\(F_t\)는 좌표가 정수/반정수인지, 좌표합이 짝/홀인지에 따라 4가지 타입(\(t=0,1,2,3\))으로 나뉜 4차원 부분집합입니다. 각 타입마다 원점에서 가장 가까운 128개 점만 코드북으로 저장하면(\(C \in \mathbb{R}^{4 \times 128 \times 4}\), 4KB), 두 4차원 인덱스의 곱으로 \(4 \times 128 \times 128 = 65536\)개의 8차원 점을 정확히 재현할 수 있습니다. 이 숫자는 원래 \(E_8\) 코드북의 전체 점 개수(\(2^{16}\))와 정확히 같습니다 — 즉 근사가 아니라 정확히 같은 코드북을 256배 적은 저장공간으로 표현하는 것이 이 방법의 핵심입니다. 디코딩은 8차원 인덱스를 \([t, i, j]\)로 쪼개 4차원 벡터 두 개를 lookup해서 이어붙이는 것뿐이라, 4KB 코드북이 GPU L1 캐시에 상주하며 반복 접근됩니다.

실제 양자화 함수 fe8quant는 벡터 \(v = [a; b]\)에 대해 다음을 풉니다.

$$ \text{fe8quant}(v, \alpha, C) = \arg\min_{t,i,j} \; \lVert v - \alpha \cdot c_{t,i,j} \rVert_2^2 $$

여기서 \(\alpha = q_{0.95}(|w_g|)/r\)는 열 단위 outlier-robust 스케일(95퍼센타일 기반), \(r\)은 코드북 반지름 하이퍼파라미터(기본값 1.75)입니다. 65536개를 전부 비교하면 느리지만, \(a, b\)가 타입 \(t\)를 공유한다는 factored 구조 덕분에 탐색이 분해됩니다.

$$ (t^*, i^*, j^*) = \arg\min_{t} \left[ \min_i \lVert a - \alpha\, c_{t,i} \rVert^2 + \min_j \lVert b - \alpha\, c_{t,j} \rVert^2 \right] $$

거리를 내적으로 치환하는 proxy-distance 항등식을 쓰면 타입당 128번, 총 \(4 \times 128 \times 2 = 1024\)번의 내적 계산으로 끝나서(원래 65536번 대비), 탐색 비용이 크게 줄어듭니다.

양자화 후 오차는 GPTQ와 동일한 Hessian 기반 보정으로 전파됩니다.

$$ \Delta W_{i,k} = -\frac{W_{i,j} - \widehat{W}_{i,j}}{H^{-1}_{j,j}} H^{-1}_{j,k}, \qquad H = 2XX^{\top} $$

이 보정의 중요한 성질은 **행 독립성(row independence)**입니다 — 벡터 \(v\)를 양자화했을 때 생기는 오차는 오직 같은 행 \(i\) 안에서만 전파되고 다른 행에는 영향을 주지 않습니다. 덕분에 GPTQ처럼 열 단위로 순차 처리하면서 Cholesky 분해로 계산량을 줄이는 최적화를 그대로 재사용할 수 있습니다.

4.2 Weight Scale Normalization. 실제 가중치 행렬은 전체적으로는 Gaussian처럼 보여도, 행/열 별로 뜯어보면 분산이 상당히 다릅니다(논문 Figure 3, OPT-6.7B out_proj 예시). 이 편차를 그대로 두고 \(E_8\) 양자화를 하면 일부 행/열에서만 오차가 커집니다. 그래서 \(W\)를 다음처럼 분해합니다.

$$ W = W' \odot (gh^{\top}) $$

\(g\)는 행 스케일, \(h\)는 열 스케일이고, \(\odot\)은 element-wise 곱입니다. 목표는 \(W'\)의 모든 행/열의 \(L_1\) 노름(평균 절댓값)이 균일해지도록 \(g, h\)를 찾는 것인데, 이는 절댓값 행렬 \(|W|\)에 대해 doubly stochastic matrix를 구하는 문제와 수학적으로 동치이고, Sinkhorn-Knopp 알고리즘의 반복 구조로 효율적으로 풀립니다 (보통 5회 미만 반복으로 수렴). \(L_2\) 대신 \(L_1\)을 쓰는 이유는, outlier 가중치는 어차피 4.3의 critical weight preservation이 별도로 처리하므로, 스케일 계산 자체는 outlier에 덜 민감한 \(L_1\)이 낫기 때문입니다.

4.3 Adaptive Critical Weight Preservation. 8차원 벡터 \(v_{b,j} = W_{8b:8(b+1),j}\)마다, 그 벡터만 양자화했을 때 늘어나는 output loss를 중요도 점수로 정의합니다.

$$ S_{b,j} = \min_{\widehat{W}(b,j)} \; \lVert WX - \widehat{W}(b,j)X \rVert_F^2 $$

Lagrange multiplier로 이 제약 최적화를 풀면(Appendix A, 4-2에서 유도 요약), 닫힌 형태로 정리됩니다.

$$ S_{b,j} = \frac{\lVert v_{b,j} - \widehat{v}_{b,j} \rVert_2^2}{\left[XX^{\top}\right]^{-1}_{j,j}} $$

이 점수가 높은 벡터를 골라 양자화하지 않고 FP16으로 보존합니다. 문제는 “얼마나 보존할지"인데, 기존 SpQR/SEPTQ처럼 전역 고정값을 쓰지 않고, 논문은 sublayer·layer마다 점수 분포의 knee point가 다르다는 걸 실증적으로 보인 뒤(Figure 4 — o_proj는 layer별 점수 스케일 자체가 크게 다르고, q_proj는 스케일은 비슷해도 knee의 percentile 위치가 다름), Kneedle 알고리즘으로 매트릭스마다 다른 임계값 \(\tau\)를 자동으로 찾습니다.

$$ x_k = \frac{k-1}{K-1}, \qquad y_k = \frac{\log s_k - \log s_K}{\log s_1 - \log s_K}, \qquad k^* = \arg\max_k \big[(1-x_k) - y_k\big], \qquad \tau = s_{k^*} $$

(\(s_1 \ge \dots \ge s_N\)은 상위 \(K = \max(2, \lfloor N\rho \rfloor)\)개 점수를 내림차순 정렬한 것, \(\rho\)는 탐색 비율 하이퍼파라미터.) 마스크는 8차원 블록 단위로 Kronecker 곱을 이용해 만들어집니다.

$$ M = \mathbf{1}_8 \otimes \mathbb{I}(S \ge \tau) $$

보존 마스크를 저장하는 데 별도 비트를 쓰지 않는 것도 이 논문의 실용적인 포인트인데, 코드북이 \(2^{16}\)개 인덱스를 갖지만 실제로 그 전부를 쓸 확률은 거의 없다는 점을 이용해서, 마지막 인덱스(\(2^{16}-1\))를 “이 벡터는 양자화하지 않고 FP16 그대로 저장"이라는 예약 코드로 재활용합니다. 별도 마스크 행렬을 저장할 필요가 없어지는 셈입니다.

4.4 The EPTQ Algorithm. 전체 파이프라인(Algorithm 3)은 다음 순서로 진행됩니다: (1) Algorithm 1로 \(W', g, h\) 계산 → (2) Hessian 역행렬을 Cholesky 분해 → (3) Algorithm 2로 critical vector mask \(M\) 계산 → (4) 블록 크기 \(B\) 단위로 열을 순회하며 각 열의 8차원 벡터를 fe8quant로 양자화하고, GPTQ 스타일로 오차를 전파 → (5) 마지막에 \(\widehat{W} = \widehat{W} \odot (gh^{\top})\)로 원래 스케일로 복원.

한 가지 흥미로운 디테일은, \(W'\)를 양자화할 때 Hessian 계산에 원래 입력 \(X\)가 아니라 \(X' = \text{diag}(h) \cdot X\)를 써야 한다는 점입니다. 원래 레이어 연산 \(Y = WX\)를 스케일 분해로 다시 쓰면:

$$ Y = WX = (W' \odot (gh^{\top}))X = \text{diag}(g)\, W' \, \text{diag}(h) \, X = \text{diag}(g)\, (W' X') $$

즉 \(W'\)의 “실질적인 입력"은 \(X\)가 아니라 \(X' = \text{diag}(h)X\)라는 걸 대수적으로 보여줍니다. 이걸 놓치면 스케일 정규화 이후의 Hessian이 실제 출력 오차를 반영하지 못하게 됩니다.

4-2. 수식/알고리즘 핵심만 발췌해 재해석

세 가지 구성요소를 한 문장씩으로 압축하면:

  • Eq.(1) 목적함수 — “가중치 오차가 아니라 출력 오차를 최소화한다"는 GPTQ류 공통 전제.
  • Eq.(2)~(3) \(E_8\) 분해 + fe8quant — “정확히 같은 코드북을, 정확히 같은 점 개수로, 4KB에 담는다"는 무손실 재구성 트릭. 탐색도 곱 구조 덕분에 \(65536 \to 1024\) 내적으로 줄어든다.
  • Eq.(4) Hessian 오차 보정 — GPTQ의 열 단위 순차 보정을 그대로 재사용 가능하게 만드는 “행 독립성"이 핵심 전제.
  • Eq.(5) 중요도 점수 — “이 벡터 하나만 양자화했을 때 늘어나는 오차"를 Lagrange multiplier로 닫힌 형태로 유도. SpQR/SEPTQ의 임계값 개념을 미분 가능한 형태로 재정의한 것에 가깝다.
  • Eq.(7)~(8) Kneedle 임계값 — “몇 % 보존"이 아니라 “곡선이 꺾이는 지점까지 보존"으로, 레이어마다 다른 민감도 분포에 자동으로 맞춘다.

Appendix B의 bits-per-weight(bpw) 공식도 실제 압축률을 이해하는 데 유용합니다. 8차원 벡터 하나는 양자화되면 16bit(2bpw), 보존되면 예약 인덱스(16bit) + FP16 8개 값(128bit) = 144bit(18bpw)를 씁니다. 보존 비율을 \(f\)라 하면,

$$ \text{bpw} = (1-f) \times 2 + f \times 18 + 16\left(\frac{1}{d_{\text{row}}} + \frac{1}{d_{\text{col}}}\right) $$

마지막 항은 스케일 벡터 \(g, h\)의 오버헤드인데, 일반적인 LLM 행렬 크기(\(d \sim 4096\text{–}11008\))에서는 0.01bpw 미만이라 무시할 수 있는 수준입니다. 즉 실제 bpw는 거의 전적으로 보존 비율 \(f\)에 의해 결정됩니다.

5-1. Baseline 대비 무엇을 개선했는가

  • 모델: Llama-2-7B/13B/70B, Llama-3-8B
  • 데이터셋: Wikitext-2, C4 (perplexity), PIQA/ARC-e/ARC-c/HellaSwag/WinoGrande (zero-shot, lm-evaluation-harness v0.4.4)
  • Calibration: C4에서 128개 샘플, 시퀀스 길이 2048로 truncate (GPTQ 관례를 그대로 따름)

  • 하드웨어: 단일 NVIDIA H100, 모든 방법 fine-tuning 없이 평가

개선 축은 세 가지로 명확히 나뉩니다: 정확도는 scalar 방법의 붕괴를 막고 VPTQ를 앞서며 QTIP과 동급, 양자화 시간은 VQ 계열 대비 최대 6.8배(QTIP, Llama-2-70B 기준) / 3.4배(VPTQ, Llama-2-70B 기준) 단축, 추론 처리량은 QTIP/VPTQ뿐 아니라 FP16 자체보다도 빠른 방법(FE8)이라는 점이 다른 baseline과 가장 크게 갈리는 지점입니다 — 단, 논문도 명시하듯 이건 Llama-2-70B를 제외한 대부분 모델에서의 결과이고, 70B에서는 QTIP과 EPTQ FE8이 비슷한 수준(38.9 vs. 36.2 tok/s)이면서 QTIP이 근소하게 더 높습니다.

6. 핵심 기여 (Contribution 요약)

  • \(E_8\) 격자를 정확히(근사 없이) 유지하면서 1MB → 4KB로 압축하는 Factored 표현을 제시해, 코드북 lookup을 GPU L1 캐시 상주 수준으로 끌어올림.
  • 코드북 학습이나 복잡한 최적화 없이, Sinkhorn-Knopp 기반 행/열 스케일 정규화만으로 격자 양자화 효율을 크게 개선.
  • Critical weight 보존 비율을 매트릭스마다 Kneedle로 자동 결정하는 adaptive threshold를 제안하고, 보존 마스크를 추가 비트 없이 코드북 예약 인덱스로 인코딩.
  • 2-bit PTQ에서 “정확도 vs 효율” 트레이드오프가 근본적인 한계가 아님을, 여러 모델 패밀리·다양한 지표(정확도/양자화 시간/추론 처리량)에 걸친 실험으로 실증.

7. 해석 포인트 / 내 생각

7-1. 왜 이 방법이 통하는지 나만의 직관

Factored-\(E_8\)이 특별한 이유는 이게 “압축을 위한 근사"가 아니라 “구조를 이용한 무손실 재인코딩"이라는 점입니다. \(E_8\)이 4차원 coset 두 개의 곱으로 정확히 분해된다는 건 이미 알려진 격자 이론이지만, 이걸 “인덱스를 두 개의 4차원 lookup으로 쪼개면 L1 캐시에 들어간다"는 시스템 레벨 이득으로 연결한 것이 이 논문의 실질적인 기여로 보입니다. Product Quantization(PQ)과 비슷한 발상처럼 보이지만, PQ는 서브벡터 코드북을 데이터로부터 학습해야 하는 반면 여기서는 격자의 대수적 구조가 분해를 보장하기 때문에 학습이 전혀 필요 없습니다 — VPTQ가 시간이 오래 걸리는 이유(코드북을 데이터로 학습)와 정확히 대비되는 지점입니다.

Weight Scale Normalization과 Critical Weight Preservation의 조합도 “관심사의 분리"로 보면 깔끔합니다. \(L_1\) 기반 스케일 정규화는 “대다수 가중치의 몸통 분포"를 맞추는 역할만 하고, outlier 처리는 아예 별도 메커니즘(4.3)에 맡깁니다. 이건 activation 쪽에서 SmoothQuant/AWQ가 outlier를 다른 텐서로 옮겨서 처리하는 것과 발상은 비슷한데, EPTQ는 weight 쪽에서 “옮기지 않고 아예 양자화 대상에서 제외"하는 더 직접적인 방식을 씁니다. 그리고 그 제외 마스크를 코드북 인덱스 공간에 끼워 넣어 오버헤드를 0으로 만든 게 실용성 측면에서 영리한 디테일이라고 생각합니다.

8. 한계와 향후 과제

  • Weight-only: activation은 양자화하지 않습니다. 논문도 결론에서 activation quantization으로의 확장을 향후 과제로 명시합니다.
  • 공식 코드/모델 미공개: 익명 심사 단계라 “accept 이후 공개 예정"이라고만 되어 있어, 실제 구현 디테일(특히 fe8quant의 GPU 커널)은 코드가 나와야 검증 가능합니다.
  • 하드웨어 특이적 이득: 4KB 코드북이 L1 캐시에 상주해서 얻는 처리량 이득은 H100 기준으로 측정된 것이라, 다른 GPU 세대(L1 캐시 크기, 메모리 대역폭이 다른)에서도 동일한 배수로 일반화될지는 추가 검증이 필요해 보입니다.
  • 보존 비율이 커질 때의 구조: critical weight preservation이 코드북의 “마지막 인덱스 1개"를 재활용하는 방식이라, 보존 비율 \(\rho\)가 커지는 극단적 설정(논문 실험은 최대 \(\rho{=}0.5\))에서 이 재활용 방식이 정말 스케일링되는지는 충분히 논의되지 않았습니다.
  • 모델별 편차: Llama-3-8B에서는 QTIP이 EPTQ(E8)보다 accuracy가 더 높은 경우가 있어(Table 1), FE8이 처리량에서 QTIP을 이겨도 정확도 최우선 시나리오에서는 여전히 QTIP이 유효한 선택지로 남습니다.
  • 하드웨어 인지 커널: 결론에서 “hardware-aware kernel 개발"을 향후 과제로 언급 — 지금 처리량 수치도 이미 인상적이지만, 아직 최적화 여지가 있다는 저자들 스스로의 평가입니다.

# 논문 Algorithm 1을 텍스트만 보고 재구성한 것 (비공식, 검증용).
# Sinkhorn-Knopp 스타일 반복으로 행(g)/열(h)의 L1 스케일을 정규화한다.
import torch

def iterative_weight_scaling(W: torch.Tensor, n_iter: int = 5, eps: float = 1e-8):
    d_row, d_col = W.shape
    g = torch.ones(d_row)
    h = torch.ones(d_col)
    W_abs = W.abs()

    for _ in range(n_iter):
        g = (W_abs / h.clamp_min(eps)).sum(dim=1) / d_col
        h = (W_abs.T / g.clamp_min(eps)).sum(dim=1) / d_row

    W_prime = W / (g.unsqueeze(1) * h.unsqueeze(0)).clamp_min(eps)
    return W_prime, g, h

# fe8quant의 분해 탐색 구조를 정리한 의사코드 (비공식, 검증용).
def fe8quant(v, alpha, codebook):
    a, b = v[:4], v[4:]
    best = None
    for t in range(4):                      # coset type
        i, dist_a = nearest(a / alpha, codebook[t])   # 128개 중 최근접
        j, dist_b = nearest(b / alpha, codebook[t])
        total = dist_a + dist_b
        if best is None or total < best[0]:
            best = (total, t, i, j)
    _, t, i, j = best
    return alpha * torch.cat([codebook[t, i], codebook[t, j]]), (t, i, j)
